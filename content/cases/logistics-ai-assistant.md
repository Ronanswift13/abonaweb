## 项目背景

企业后勤服务涉及访客接待、会议保障、设施报修、餐饮服务等多个环节。以访客预约为例，申请人需要在移动办公 App 中逐项填写到访时间、事由、被访人、同行访客及其证件信息，被访人再单独审批，填写繁琐、容易出错。

项目来源于《面向后勤多场景服务的人工智能助手关键技术研究》，目标是让员工“说一句话”就能办完后勤业务，同时满足企业对数据安全与操作合规的要求。

## 解决方案

助手作为独立页面部署，嵌入企业移动办公 App 使用，用户身份由宿主 App 传入并校验：

```
宿主传入身份 → 语音转写 → 意图识别 → 槽位抽取 → 规则校验 → 确认卡 → 创建或审批 → 回到宿主
```

1. **语音一句话办理**：内网部署的语音识别模型转写 16k 中文语音，术语规则库负责口语清洗与纠错，“下周三下午两点到四点”等时间说法自动归一；
2. **意图与信息理解**：Chinese-MacBERT 意图模型结合对话状态识别六类意图；槽位抽取规则优先，规则抽不出且原话有线索时才调用内网大模型补全，大模型输出必须是用户原话的子串；
3. **号码只认规则**：身份证按 GB 11643 校验位、手机号按号段校验，任何模型都不生成、不补全号码；
4. **确认卡把关**：缺什么问什么，两个日期、两个被访人等冲突标红交用户点选；只有用户在确认卡上点击确认，才会调用业务接口；
5. **MCP 工具闭环**：预约创建、审批、人员校验等接口统一注册为 MCP 工具，编排引擎只认工具名；幂等键防重复提交，接口超时重试一次仍失败则保留草稿。

## 安全设计

- 证件号、手机号全局日志掩码，审计中的提交内容 AES-256-GCM 加密；
- 语音只在内存中转写，转写后立即丢弃，不落盘、不进提示词；
- 不拉取、不缓存组织树与通讯录，无跨会话记忆；
- 大模型地址守卫只允许内网私有化模型，模型不可用时转为表单确认，不转调任何外部平台；
- 申请人口头说“同意”无效，审批只认被访人本人点击确认，越权尝试全部入审计。

## 项目进展

工程框架、语音与意图、规则与编排、接口闭环、安全与联调、指标与成套六个研发阶段均已完成复验；部署包支持一键安装、升级与回滚，并完成 Linux 部署演练。宿主 App 真实环境联调、第三方测试与现场试点将在客户环境就绪后开展。
